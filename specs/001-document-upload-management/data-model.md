# Data Model: Document Upload and Management

## Document

Represents one accepted uploaded file.

Fields:

- `DocumentId`: integer primary key.
- `Title`: required, bounded text.
- `Description`: optional text.
- `Category`: required text from the six specified categories.
- `Tags`: searchable user-provided tags, stored as normalized values.
- `OriginalFileName`: display-only source name; never used as a storage path.
- `FilePath`: required relative path beneath the configured upload root.
- `FileType`: required MIME type, maximum 255 characters.
- `FileSize`: required positive byte count, maximum 25 MB.
- `UploadedByUserId`: required foreign key to User.
- `UploadedDate`: UTC timestamp.
- `ProjectId`: optional foreign key to Project.
- `TaskId`: optional foreign key to TaskItem.
- `IsDeleted`: lifecycle marker used to preserve audit references while excluding the file
  from normal lists; physical storage is removed during the same authorized delete flow.

Validation: title/category are required per file; extension and MIME type are allow-listed;
size is at most 25 MB; project/task associations require authorization; storage path must be
generated by the server and remain relative to the upload root.

## DocumentShare

Represents explicit access granted by an owner.

Fields:

- `DocumentShareId`: integer primary key.
- `DocumentId`: required foreign key.
- `UserId`: nullable recipient user for non-project sharing.
- `ProjectId`: nullable existing project team target for project-document sharing.
- `SharedByUserId`: required actor foreign key.
- `SharedDate`: UTC timestamp.
- `RevokedDate`: nullable UTC timestamp.

Validation: exactly one recipient target is required; project targets are allowed only for a
document associated with that project; the owner is the only user who grants or revokes
explicit shares.

## DocumentActivity

Immutable audit record for upload, download, preview, replacement, deletion, or share.

Fields: integer `DocumentActivityId`, nullable `DocumentId` for retained records after
deletion, actor `UserId`, action text, UTC `OccurredDate`, and optional detail text.

Lifecycle: retain for the document lifetime and at least 12 months after the activity. It is
not removed immediately when the document is deleted.

## DocumentTag

Normalized searchable tag associated with a document. Fields are integer `DocumentTagId`,
`DocumentId`, and bounded normalized `Value`. Duplicate values for one document are rejected.

## Relationships and access

- User 1-to-many Document through `UploadedByUserId`.
- Project 1-to-many Document through optional `ProjectId`.
- TaskItem 1-to-many Document through optional `TaskId`; a task document must use the task's
  project when one exists.
- Document 1-to-many DocumentShare and DocumentActivity.
- Document 1-to-many DocumentTag.
- Project membership grants project-document access; explicit shares grant additional access
  to named users; administrators retain full access.

## Upload state transition

`Selected` -> `Validated` -> `Scanned` -> `Stored` -> `MetadataPersisted` -> `Available`.

Any validation, scan, file-write, or metadata-save failure transitions to `Rejected` or
cleanup, removes any partial file, and exposes neither an available document nor incomplete
metadata. Replacement uses the same sequence and preserves the previous available file until
the replacement succeeds.
